# Diff — 단일 HTML 텍스트 비교 도구

`dist/diff.html` 파일 하나만 있으면 됩니다. 브라우저로 열면(`file://`도 됨) 네트워크 없이 완전히 동작하고, 아무것도 전송하거나 저장하지 않습니다.

두 텍스트를 줄 단위로 비교해 차이를 보여 주고, GNU `diff -u` 형식의 unified patch를 내보냅니다.

## 사용법

1. `dist/diff.html`을 브라우저로 엽니다.
2. 왼쪽(원본)과 오른쪽(변경본)에 텍스트를 붙여넣거나, **파일 열기** 버튼을 누르거나, 파일을 패널에 끌어다 놓습니다.
   - 파일 두 개를 한 번에 끌어다 놓으면 왼쪽·오른쪽에 차례로 들어갑니다.
   - **⇄** 버튼으로 좌우를 바꿉니다.
   - 패널 머리에 줄 수, `CRLF`, `BOM`, `끝 개행 없음` 배지가 표시됩니다.
3. **비교**(또는 `Ctrl`/`⌘`+`Enter`)를 누릅니다.
4. 결과 화면
   - 요약: `+추가 −삭제 · 변경 N곳`
   - **나란히 / 통합** 보기 전환. 화면 폭이 768px보다 좁으면 기본으로 통합 보기가 됩니다.
   - 줄 안에서 바뀐 단어·기호는 더 진한 배경으로 강조됩니다.
   - 바뀌지 않은 긴 구간은 `⋯ N줄 숨김`으로 접힙니다. 클릭하면 펼쳐지고, **모두 펼치기**로 전부 펼칩니다.
   - 파일 끝에 개행이 없는 줄에는 `⏎ 없음` 표식이 붙습니다.
5. **patch** 버튼으로 unified patch를 보고, 복사하거나 다운로드합니다(`<왼쪽 파일명>.diff`, 파일이 없으면 `changes.diff`).

## 키보드 단축키

| 키 | 동작 |
|---|---|
| `Ctrl`/`⌘` + `Enter` | 비교 |
| `Esc` | 결과에서 입력으로 돌아가기 · 창 닫기 |
| `n` / `j` | 다음 변경 |
| `p` / `k` | 이전 변경 |

`n`/`p`/`j`/`k`는 입력 칸에 포커스가 없을 때만 동작합니다. 상단 바의 ▲/▼ 버튼도 같습니다.

## 옵션

| 옵션 | 의미 |
|---|---|
| 공백 무시 | 모든 공백 문자(탭, 줄 끝 CR 포함)를 지우고 비교합니다(GNU `-w` 상당). 화면에는 원문이 보입니다. |
| 대소문자 무시 | 소문자로 바꿔 비교합니다(GNU `-i` 상당). |
| 빈 줄 무시 | 추가·삭제된 줄이 **전부** 빈 줄인 변경은 "무시됨"으로 흐리게 표시하고 통계·이동·접기에서 뺍니다. 공백 무시가 켜져 있으면 공백만 있는 줄도 빈 줄로 봅니다. |
| 컨텍스트 | 변경 앞뒤로 보여 줄 줄 수(0/3/5/10/전체). patch의 컨텍스트 줄 수도 같습니다. |
| 테마 | 시스템 / 라이트 / 다크. 페이지를 닫으면 잊습니다. |

**무시 옵션과 patch**: 무시 옵션이 켜진 상태의 patch는 GNU `diff -w/-i/-B`와 같은 성격입니다. 컨텍스트 줄은 왼쪽 원문으로 쓰이고, 무시된 차이는 patch에 반영되지 않습니다. 무시된 빈 줄 변경이 다른 변경과 가까이(컨텍스트 2배 이내) 있으면 같은 hunk 안에 `+`/`-`로 함께 나옵니다.

## 동작 규칙

- 줄은 `\n` 기준으로만 나눕니다. `\r`은 줄 내용에 남습니다. 그래서 옵션 없이 CRLF 파일과 LF 파일을 비교하면 모든 줄이 다르게 나옵니다(공백 무시를 켜면 같아집니다). 변경된 줄에서는 `\r`이 `␍`로 보입니다.
- 마지막 줄의 끝 개행 유무가 다르면 그 줄은 항상 다른 줄입니다(GNU diff와 같음). 이 규칙은 무시 옵션과 무관합니다.
- 생성한 patch는 GNU `patch`로 원본에 적용하면 대상 파일과 바이트 단위로 같습니다(무시 옵션이 없을 때).

## 알려진 한계

- **최소 diff가 아닐 수 있는 경우**: 계산 시간을 제한하려고, 서로 많이 다른 큰 입력에서는 휴리스틱으로 전환합니다. 결과는 여전히 정확한(적용 가능한) diff이지만 편집 수가 최소가 아닐 수 있으며, 이때 결과 위에 "대용량 입력이라 최소 diff가 아닐 수 있음" 배지가 나옵니다. 약 2만 줄 이하 입력은 항상 최소 diff입니다.
- 파일은 **UTF-8**로만 읽습니다(인코딩 자동 감지 없음). BOM은 지우지 않고 그대로 비교합니다.
- 앞 8KB에 NUL 바이트가 있는 파일은 **바이너리**로 보고 비교하지 않습니다.
- 50MB를 넘는 파일은 불러오기 전에 확인을 받습니다.
- 브라우저 textarea는 붙여넣은 텍스트의 `\r`을 지웁니다. CRLF를 그대로 비교하려면 파일 열기나 끌어다 놓기를 쓰세요(파일에서 읽은 원문은 textarea 내용을 고치지 않는 한 그대로 비교됩니다).
- 3-way merge, 디렉터리 비교, 바이너리·이미지 비교, patch 적용 UI는 없습니다.

## 개발

필요: Node 22 이상, GNU diffutils와 GNU patch(검증용). Windows에서는 Git for Windows에 들어 있는 것을 자동으로 찾습니다.

```
npm install
npx playwright install chromium
npm run all
```

| 명령 | 내용 |
|---|---|
| `npm run check-env` | Node·GNU diff·GNU patch 확인, 경로를 `tmp/env.json`에 저장 |
| `npm test` | 단위 테스트 (O(NM) LCS 참조 구현과 1만 2천 케이스 대조 포함) |
| `npm run fuzz` | GNU diff/patch 대조 퍼징. `--cases N --seed S --random-seeds R --core PATH --jobs J` |
| `npm run perf` | 성능 시나리오 P1~P5. `--sweep`이면 budget별 측정 |
| `npm run build` | `dist/diff.html` 생성 + 자동 검사(외부 참조 0, 코어 해시 일치) |
| `npm run e2e` | 빌드 후 Playwright E2E (데스크톱·모바일 × 라이트·다크 × Worker·메인 스레드) |
| `npm run all` | 위 전부를 순서대로 (앞 단계가 실패하면 중단) |

### 구조

```
src/core/diff-core.js   엔진 (DOM 없음 — 메인 스레드·Web Worker·Node에서 같은 소스)
src/ui/                 index.html 템플릿, styles.css, app.js
scripts/                build.mjs, check-env.mjs, env.mjs
test/unit/              단위 테스트 (node:test)
test/fuzz/              퍼징 (gen.mjs 입력 생성, fuzz.mjs 검사)
test/perf/              성능 측정
test/e2e/               Playwright
test/regressions/       퍼징에서 나온 실패 케이스 (현재 없음)
dist/diff.html          배포 파일
```

엔진: Myers O(ND) 선형 공간 알고리즘(명시적 스택, 공통 앞뒤 제거, 상대편에 없는 줄 사전 확정), GNU diff의 경계 이동(`shift_boundaries`) 이식, 줄 안 단어 단위 diff. 계산은 Web Worker에서 하고 실패하면 메인 스레드로 넘어갑니다(`?worker=0`이면 강제로 메인 스레드).

자세한 설계 결정은 [diff_plan.md](diff_plan.md), 실행 기록은 [PROGRESS.md](PROGRESS.md)에 있습니다.
